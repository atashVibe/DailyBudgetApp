# Shared UI polish — November 23, 2026

This follows the owner's visual/UX brief. The subscription foundation is a separate checkpoint (`2cc60e0`, PR #16). These UI changes use the existing Expo/React Native/Firebase app, service functions, permission checks and account-deletion safeguards. There is no new UI dependency, database model, collection or backend endpoint in this visual pass. The explicitly requested Account route is the only new UI destination here; it reuses the existing Settings screen's profile/deletion handlers.

## Delivery order and files

1. **Tokens and controls.** `app/components/common/dashboardStyles.ts` contains shared colors, spacing, typography and card styles. `PrimaryButton`, `AppTextInput`, `AppPicker`, `AppScreen`, `FormLabel`, `LoadingSpinner` and the new presentation-only `AppText` apply them across web/native screens. Inter and its OFL license are bundled in `assets/Inter.ttf` and `assets/Inter-LICENSE.txt`, using the already-installed `expo-font`. The root layout has a brief loading skeleton and bounded system-font fallback; existing authentication/resume/Stack behavior is retained.
2. **Family Settings.** `app/(drawer)/settings.tsx` and the existing `FamilyBudgetSection`, `ProfileNameSection`, `AdminsSection` and `BudgetAreasSection` now present cards, a budget edit/save/cancel state, save-on-change names, initials/Admin badges, and nested budget areas. Existing category loading and writes are reused. No separate area-filter dropdown/category block remains.
3. **Sheets and category rows.** `CategoriesSection` reuses the existing category services and icon library. Compact rows have icon tiles, type captions, receipt switches and accessible actions. Add/edit uses `SettingsSheet` as a phone bottom sheet or centered wide-screen dialog; four type chips replace the old dropdown. Empty/duplicate names show inline errors. Existing Premium checks and the ability to turn off an old requirement remain. `Toast` displays successful saves/updates; existing errors remain visible.
4. **Account.** `app/(drawer)/account.tsx` renders the existing Settings component in personal-account mode. Family Settings no longer shows deletion. `AccountSection` now opens from a quiet red row, while preserving DELETE entry, password/Google confirmation, account identity binding, preparation/retry, cancellation and sole-administrator protections. Shared-data cleanup behavior is unchanged; the separate former-family attribution cleanup roadmap item remains open.
5. **Drawer.** `app/(drawer)/_layout.tsx` adds the Account item, icons, family/name header, existing Auth photo or initials, soft teal selection and quiet sign-out. The header reads the existing family record; no schema or permission changes are made. Decorative icon glyphs are hidden from accessibility and each item has an explicit label. The old Switch User shortcut is removed as requested; sign-out and subsequent sign-in remain available. The existing drawer library supplies its slide animation and gesture behavior, with a darker overlay.
6. **Family Receipts.** `ReceiptPanel` and `ReceiptStorage` use plain language, hide an unused 0/0 meter, retain meaningful usage/deadlines, and show the receipt empty state. Subscription unavailability stays on the plan-management screen so the app does not imply checkout works. Receipt viewing/upload/deletion/export calls and limits are unchanged.
7. **Other shared screens.** Dashboard, entry controls, recent entries, authentication, invitations, plan/review pages and public information use the same text/control styles and sentence-case labels. User-entered family/category names keep their original capitalization. Narrow recent-entry action rows wrap so their targets remain usable. Existing dashboard calculations, periods, form expansion/Edit scrolling and navigation confirmation remain in place.

## Deliberate choices

- White normal-size text on requested `#0F9D88` is **3.39:1**, below WCAG AA's 4.5:1. Primary buttons use the supplied darker `#0C8573` (**4.55:1**); `#0F9D88` remains the focus/accent color. Pressed/hovered buttons use dark teal. Danger red `#DC2626` gives **4.83:1** against white. Shared body/helper/name colors and tinted badges use the defined tokens.
- Inputs use 48px height and 16px text; retaining 16px input text avoids Safari focus zoom while body text uses 15px. Shared text defaults to automatic direction, and names retain Unicode/RTL text. Information glyphs remain uniformly 20px with an invisible 48px touch area.
- Category defaults remain available in the actions menu. Removing that working feature would conflict with the owner's preservation rule. Category counts use already-loaded area data; untouched collapsed areas offer “View categories” rather than inventing a count or adding aggregate data calls.
- Custom profile-photo upload/avatar selection is **not implemented**: that would need persistence/storage changes prohibited by this visual-only brief. Existing Auth photos and initials are shown. The native drawer's animation is retained rather than modifying library internals to force an exact duration.
- Existing light UI and automatic status-bar behavior are retained; no new theme system or dark-mode state is introduced. Existing deletion/business policies and the remaining account-attribution/payment/recovery gates are not changed by styling.

## Preview and verification

The work is on `codex/shared-ui-polish`, above the separate subscription branch. It is not live until reviewed backend/rules dependencies and frontend publication are coordinated. Live Google/Apple purchases, real invitation-email delivery and physical-device behavior must not be inferred from local screenshots or emulators.

- **Web:** install the repository dependencies, configure the existing Firebase/receipt endpoint environment, and use `npm run web`. For safe automated testing use `npm run test:accounts:browser`, which starts only local `demo-dailybudget-receipts` emulators with disposable `@example.test` accounts. It runs receipt/sign-in regressions, invitation/Premium/visual cases, then protected account-deletion cases in fixture order. Use a 360px viewport and wide web viewport for the bottom-sheet/dialog variants. Never point these fixtures at production.
- **Android:** use a new development/preview build following the repository's existing EAS configuration, open the app and test the same cards/sheets, keyboard, drawer and Edit behavior at normal and enlarged font sizes. The underlying subscription checkpoint adds the native `expo-iap` module, so an old binary or Expo Go is not payment-test evidence. Do not enable purchases before store tests pass.
- **iOS:** use the existing development/TestFlight workflow on an actual device. Verify safe areas, keyboard/input zoom, RTL names, sheets, account confirmation and dashboard Edit reveal. iPhone-configured WebKit checks help with browser rendering but are not physical-iPhone/native proof. Apple sign-in remains deferred; the existing Google/password safeguards are preserved.

Local TypeScript/lint checks pass before browser verification. The first browser run passed Google sign-in and shared receipt management, then exposed drawer icon glyphs polluting accessible button names. Explicit labels/decorative-icon handling correct that issue. The follow-up browser run and screenshot review are in progress; record final results separately before publication.
